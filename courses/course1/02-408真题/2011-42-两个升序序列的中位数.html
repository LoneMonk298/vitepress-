2011·42 两个升序序列的中位数：从归并计数到双数组折半 ​

本文改写自 CodeBrick 408 数据结构讲义 · 2011·42 两个升序序列的中位数，原文链接保留。

这是 12 道「尽可能高效」真题里唯一一道最优解达到 O(log⁡n) 的——从暴力解的 O(n) 升级过去，跨过的是一整个数量级。

1. 题目与评分定位 ​

符号约定 ​

符号含义备注
L序列长度L≥1
n两个序列各自的长度题设 A、B 等长
A,B两个升序序列各含 n 个元素
⌈L/2⌉中位数位置升序序列中第 ⌈L/2⌉ 个
[s1..e1]A 的当前搜索段每轮折半收缩
[s2..e2]B 的当前搜索段与 A 段始终等长

题目原文 ​

一个长度为 L（L≥1）的升序序列 S，处在第 ⌈L/2⌉ 个位置的数称为 S 的中位数。例如，若序列 S1=(11,13,15,17,19)，则 S1 的中位数是 15。两个序列的中位数是含它们所有元素的升序序列的中位数。

现有两个等长的升序序列 A 和 B，试设计一个在时间和空间两方面都尽可能高效的算法，找出两个序列 A 和 B 的中位数。要求：

  1. 给出算法的基本设计思想
  2. 根据设计思想，采用 C、C++ 或 Java 语言描述算法，关键之处给出注释
  3. 说明你所设计算法的时间复杂度和空间复杂度

总分 15 分（正确性 11 分、最优性 4 分）。

关键翻译 ​

把定义翻译成可操作的目标

A、B 各长 n，合并后总长 2n，按题面定义中位数是第 $\lceil 2n/2 \rceil = $ 第 n 个（从 1 起数）。

这个「第 n 个」是整道题的目标，所有算法都在朝它收敛。

2. 暴力解：归并计数 ​

设计思想 ​

最自然的想法就是归并：两个指针分别指向 A、B 的开头，每次取较小者前进一步——这正是归并排序合并阶段的动作。数到第 n 个取走的元素，它就是答案。

而且我们只要这个值，不需要合并后的完整序列，所以连结果数组都不用开。

代码实现 ​

c
int median(int A[], int B[], int n) {
    int i = 0, j = 0;              // 分别指向 A、B 的当前元素
    int cur = 0;                   // 最近一次被取走的值
    for (int k = 0; k < n; k++) {  // 归并着数，取满 n 个停
        if (A[i] <= B[j])
            cur = A[i++];          // A 的当前值更小，取它
        else
            cur = B[j++];
    }
    return cur;                    // 第 n 个被取走的就是中位数
}

边界论证 ​

循环体内 i、j 永远不会越界

每取走一个元素，i+j 恰好加 1；循环最多执行 n 次，所以取数前始终有 i+j<n，即 i<n 且 j<n——两个下标都停在各自数组内。

连「某一路耗尽」的分支都不需要。

验证题面例子：A=(11,13,15,17,19)、B=(2,4,6,8,20)，归并前 5 步依次取走 2,4,6,8,11，第 5 个是 11。

指标值说明
时间O(n)一遍归并数 n 步
空间O(1)只用 i、j、cur 三个标量

要避开的更差变体 ​

别先合并再取

先把 A、B 完整合并进一个 2n 的辅助数组，再取第 n 个。

答案没变，却白花了 O(n) 空间——时间和空间两档全丢，只剩正确性基础分。

同样是暴力，「归并着数、不存结果」和「先存下来再数」之间已经隔着一档分。

3. 暴力解的浪费在哪 ​

三问审查 ​

一、有没有重复扫描？

没有，每个元素至多看一次。

二、有没有重算已知的东西？

没有。

三、有没有放着性质不用？

有。

浪费在哪：只用了局部信息

A 和 B 都是全局升序的，但归并每次比较只用了「当前两个队头谁小」这一点局部信息，一次比较只淘汰 1 个元素。

换个角度看更明显：归并顺带生产了「前 n 个元素的完整出场顺序」，而题目只要第 n 个——为一个值生产了一整段序列，这就是过剩。

升序能一次淘汰半段 ​

取 A 当前段的中位数 a、B 当前段的中位数 b（两段始终等长）：

情形推论裁剪结果
a=b两边各有一半元素 ≤ 它它就是合并后的中位数，直接返回
a<bA 左半全 ≤a<b（靠前）；B 右半全 ≥b>a（靠后）保留「A 右半 + B 左半」
a>b对称保留「A 左半 + B 右半」

一次比较砍掉近一半搜索范围——这就是对数复杂度的来源。

4. 最优解：双数组同时折半 ​

设计思想 ​

维护 A 的当前段 [s1..e1] 和 B 的当前段 [s2..e2]，按上面的判定每轮裁剪，直到两段各剩 1 个元素，返回较小者。

代码实现 ​

c
int median(int A[], int B[], int n) {
    int s1 = 0, e1 = n - 1;            // A 当前段 [s1..e1]
    int s2 = 0, e2 = n - 1;            // B 当前段 [s2..e2]

    while (s1 < e1 || s2 < e2) {
        int m1 = (s1 + e1) / 2;
        int m2 = (s2 + e2) / 2;
        int len = e1 - s1 + 1;          // 当前段长（A 与 B 等长）

        if (A[m1] == B[m2]) return A[m1];

        if (A[m1] < B[m2]) {
            // 中位数在 A 右半 + B 左半
            if (len % 2 == 0) { s1 = m1 + 1; e2 = m2; }   // 偶：切掉含 m1 的左半
            else              { s1 = m1;     e2 = m2; }   // 奇：保留 m1
        } else {
            // 中位数在 A 左半 + B 右半
            if (len % 2 == 0) { e1 = m1; s2 = m2 + 1; }
            else              { e1 = m1; s2 = m2;     }
        }
    }

    // 两段各剩 1 个，较小者就是合并序列的第 n 个
    return A[s1] < B[s2] ? A[s1] : B[s2];
}

手工走一遍 ​

用题面例子：n=5，A=(11,13,15,17,19)，B=(2,4,6,8,20)

轮当前段比较裁剪
1A[0..4], B[0..4]，len=5 奇A[2]=15>B[2]=6e1=2, s2=2
2A[0..2], B[2..4]，len=3 奇A[1]=13>B[3]=8e1=1, s2=3
3A[0..1], B[3..4]，len=2 偶A[0]=11>B[3]=8e1=0, s2=4
4A[0..0], B[4..4]，退出—返回 min(11,20)= 11

复杂度 ​

指标值说明
时间O(log⁡n)每轮段长减半，迭代次数 ≤log2⁡n+1
空间O(1)只用 s1/e1/s2/e2/m1/m2/len 几个标量

两个约束同时达标，这就是标准答案。

5. 四个易错细节 ​

这道题的坑比一般的二分密集得多。

易错点一：等长不变量必须明确陈述并维护

循环不变量「两段始终等长」必须明确陈述。

整套判定的合法性建立在它上面：两段等长时，段中位数的比较才对应全局中位数的语义。丢了这条不变量，m1、m2 的比较就漂移了，按算法错处理。

易错点二：奇偶必须分开切

这是等长不变量的技术保障：

  • 段长为偶时：含中位数下标的那一半整段切掉（含中元素也丢），不含中的那段保留含中位置
  • 段长为奇时：两段都保留各自的中元素

不分奇偶（全部 m+1 或全部 m）会让两段长度错开，后续判定全部失效。

易错点三：退出条件是 s1 < e1 || s2 < e2

任何一段还能缩就继续。写成 && 会在一段先缩到 1 时提前退出，另一段还没缩完。

易错点四：终态返回较小者

合并后的第 n 个小于第 n+1 个，两段各剩 1 个时答案是 min(A[s1],B[s2])——返 max 是这道题的经典错点，一字之差按错处理。

另外 a=b 的分支要立刻返回，它已经是答案。

6. 等价方法与升级空间 ​

等价方法对比 ​

方法时间空间判分定位说明
归并计数O(n)O(1)丢时间档公认保底解，只丢时间
先合并再取O(n)O(n)两档全丢暴力里更差的一档，没有理由选
双数组折半O(log⁡n)O(1)满分唯一同时达标

升级空间 ​

不等长推广

本题是「两个有序数组找第 k 个」问题族的等长特例——等长让算法格外干净，每轮两段各切一刀。

它的不等长推广（任意长度的两个有序数组求中位数）要先处理段长悬殊的情况，难度陡增；学透等长版的「比较段中位数、整段淘汰」思想，是啃下推广版的最短路径。

考场策略

考场上折半的奇偶细节没把握时，交一份写对的归并远好过交一份切法写错的折半——后者连正确性都保不住。

7. 总结 ​

对比项归并计数双数组折半
时间O(n)O(log⁡n)
空间O(1)O(1)
得分正确性满分，丢时间档满分
核心逐个淘汰 1 个元素比较段中位数，整段淘汰
关键坑—等长不变量 + 奇偶分开切

备考要点

这是 12 道「尽可能高效」真题里唯一一道 O(log⁡n) 的题。

从 O(n) 到 O(log⁡n) 跨过的是一个数量级，但代码只多了十几行——性价比极高。理解「一次比较淘汰半段」的论证，比背代码重要得多。
