算法和算法评价 ​

本文改写自 CodeBrick 408 数据结构讲义 · 算法和算法评价，原文链接保留。

0. 这一节在问什么 ​

三个我一开始没想清楚的问题：

  1. 一段代码快不快，为什么不能直接跑一遍计时？
  2. 递归没有循环可数，复杂度到底怎么算？
  3. 为什么说「时间数结点、空间数高度」？

这一节给的是复杂度分析的全部方法论——后面每一章算复杂度都回来用它。

1. 什么算算法，什么算好算法 ​

问题的来源：程序 ≠ 算法 ​

操作系统的主循环是个正经程序，却永远不停。

所以「算法」比「程序」多一条硬约束：必须能在有穷步内结束。

五个特性，缺一不可 ​

特性含义反例
有穷性有穷步内结束，每步也在有穷时间内完成while(1) x++;；操作系统主循环
确定性每种情况的操作都有确切规定，无二义性「把较大的放前面」——相等时没规定
可行性都能由已实现的基本运算执行有限次完成「取 π 的全部小数位求和」
输入零个或多个打印九九乘法表没有输入，允许
输出一个或多个无输出的算法没有意义

最容易考的边界

算法必须有穷，程序不必——操作系统等待循环是程序，但不是算法（殷人昆 p24 明确点出）。

另外：算法可以用自然语言或流程图描述，程序必须用程序设计语言写成、能被执行。

四条评价标准 ​

标准说明
正确性能正确解决问题
可读性便于阅读、理解、交流
健壮性对非法输入能作出恰当反应
高效性含时间与空间两面，常常此消彼长，一般以时间为主

2. 时间复杂度怎么数：只数基本操作 ​

为什么不能直接计时 ​

方法缺陷
事后统计（跑一遍计时）① 必须先把算法实现出来；② 结果严重依赖机器和编译器，换台电脑就变
事前分析估算（数执行次数）无——实际采用

所以思路是：不看时间，只数执行次数。

只数一条语句就够了 ​

概念含义
语句频度一条语句的重复执行次数
T(n)全部语句频度之和
基本操作嵌套最深、次数最多的那条语句（查找类看关键字比较，排序类看比较与移动）

为什么数一条就够

剩下的部分只贡献常数系数和低次项，而大 O 恰好把这两样丢掉。

T(n) 的量级 = 基本操作的频度

三个记号的分工 ​

记号 / 规则含义
大 O存在 c,n0 使 n≥n0 时 T(n)≤cf(n)，渐近上界
Ωn≥n0 时 T(n)≥cg(n)，渐近下界
Θ同时是 O 与 Ω，上下界同阶
加法与乘法规则并列取 O(max(f,g))，嵌套取 O(f⋅g)；与 n 无关的常数记 O(1)
取最紧上界不唯一，习惯取最紧的上界、最大的下界

常见量级（带实感） ​

量级（递增）典型算法109 次操作/秒、n=106 时
O(1) 常数阶下标访问、散列查找（理想）瞬时
O(log⁡n) 对数阶折半查找、二叉排序树查找瞬时
O(n) 线性阶顺序查找、遍历一遍表1 ms
O(nlog⁡n) 线性对数阶快排（平均）、归并、堆排序20 ms
O(n2) 平方阶直接插入、起泡、简单选择排序约 17 分钟
O(n3) 立方阶三重循环（如 Floyd）约 32 年
O(2n) 指数阶穷举子集、汉诺塔无法完成
O(n!) 阶乘阶穷举排列无法完成

这张表只在 n 足够大时成立

渐近分析丢掉的常数在小规模下可能占主导：n<1000 时 n2 反而比 1000n 快。

快速排序在子表足够小时改用直接插入排序，依据就是这一条。

3. 数循环：看循环变量怎么长 ​

核心原则 ​

每次加一个常数 → 线性；每次乘一个常数 → 对数；被平方约束 → 平方根。

七种形态 ​

形态代码骨架精确次数量级
1 单层线性for(i=0;i<n;i++)nO(n)
2 嵌套独立内层上界与外层无关n×mO(nm)
3 嵌套相关for(j=1;j<=i;j++)n(n+1)/2O(n2)
4 倍增i=1; while(i<=n) i*=2;⌊log2⁡n⌋+1O(log⁡n)
5 折半i=n; while(i>1) i/=2;⌊log2⁡n⌋O(log⁡n)
6 平方比较for(i=0;i*i<=n;i++)⌊n⌋+1O(n)
7 两段并列两段顺序执行相加取较大者

坑一：形态 4 与形态 5，量级相同但次数差一 ​

形态代码次数n=8
形态 4（倍增）i=1; while(i<=n) i*=2;⌊log2⁡n⌋+14 次
形态 5（折半）i=n; while(i>1) i/=2;log2⁡n3 次

这里不能写成 ⌈log2⁡n⌉

n=8 时形态 4 执行 4 次，而 ⌈log2⁡8⌉=3。

差别来源是边界：形态 4 在 i=1 时循环体执行了一次（从 1 撑到 n），形态 5 在 i=1 时不再执行（从 n 缩到 1）。

盯住「循环体在边界值上执不执行」就不会记混。

坑二：嵌套循环不是一律相乘 ​

内层上界跟着外层变时，必须求和

只有内层上界与外层无关时才是形态 2 的相乘。

内层上界或步长跟着外层变（如 for (j = 1; j <= n; j += i)），次数由起点、终点、步长共同决定，得老老实实求和——那种情形总次数是 Θ(nlog⁡n)，不是 O(n2)。

顺带：频度怎么数 ​

c
int MatrixSum(int a[][N], int n) {
    int sum = 0;                      /* 频度 1 */
    for (int i = 0; i < n; i++)       /* 条件判断 n+1 次（最后一次为假才跳出）*/
        for (int j = 0; j < n; j++)   /* 对每个 i 判断 n+1 次，共 n(n+1) 次 */
            sum += a[i][j];           /* 频度 n²，这是基本操作 */
    return sum;                       /* 频度 1 */
}
T(n)=1+(n+1)+n(n+1)+n2+1=2n2+2n+3

和基本操作的频度 n2 只差常数系数与低次项——这就是「数最内层那一条就够」的由来。

两处容易漏

循环的条件判断比循环体多一次；内层判断是 n(n+1) 而不是 n2。

4. 数递归：写方程再逐层展开 ​

方法 ​

递归没有循环变量可数，得先写递归方程（递归项 + 非递归项 + 边界条件），再逐层展开：反复代入自身直到看出规律，用边界条件收尾。

三种基本形态 ​

递归式解典型来源规模怎么缩
T(n)=T(n−1)+1Θ(n)阶乘、单链表递归遍历每次减 1
T(n)=T(n/2)+1Θ(log⁡n)折半查找（只进一个子区间）每次减半
T(n)=2T(n−1)+1Θ(2n)汉诺塔，精确解 2n−1减 1 但派生两个
T(n)=2T(n/2)+nΘ(nlog⁡n)归并排序减半且派生两个
T(n)=T(n−1)+nΘ(n2)每层还要扫一遍整表减 1，每层代价 n

减 1 和减半是两回事

前者线性、后者对数。递归本身不带来任何量级，量级来自规模缩小的方式。

展开过程举例 ​

以减半为例（折半查找）：

T(n)=T(n2)+1=T(n4)+2=⋯=T(n2k)+k

令 n2k=1 得 k=log2⁡n，代回：

T(n)=1+log2⁡n=Θ(log⁡n)

汉诺塔（每层派生两个、规模减 1）：

T(n)=2T(n−1)+1=⋯=2n−1=Θ(2n)

递归树与主定理 ​

递归树：把每层代价摊在树上逐层求和

适合 T(n)=aT(n/b)+f(n)。以归并排序的 T(n)=2T(n/2)+n 为例：

第 i 层有 2i 个子问题、每个规模 n/2i、每个的非递归代价 n/2i，故该层总代价 =2i×n/2i=n，与层号无关；规模从 n 折半到 1 共 log2⁡n+1 层，总代价 =Θ(nlog⁡n)。

「每层 O(n)、共 O(log⁡n) 层，故 O(nlog⁡n)」——这句话就是递归树法的完整推导，归并和快排的复杂度都是这么来的。

主定理：比 n^log_b a 与 f(n) 谁大

对 T(n)=aT(n/b)+f(n)，记 d=logb⁡a：算出 nd 跟 f(n) 比，大的赢；一样大就再乘一个 log⁡n。

情形条件结论
1f(n)=O(nd−ε)T(n)=Θ(nd)
2f(n)=Θ(nd)T(n)=Θ(ndlog⁡n)
3f(n)=Ω(nd+ε) 且 af(n/b)≤cf(n)T(n)=Θ(f(n))
递归式nlogb⁡af(n)结论出现在
T(n)=T(n/2)+O(1)11Θ(log⁡n)折半查找
T(n)=2T(n/2)+O(1)n1Θ(n)二叉树遍历
T(n)=2T(n/2)+O(n)nnΘ(nlog⁡n)归并排序

主定理的适用条件

只适用于规模按倍数缩小的 T(n)=aT(n/b)+f(n)。

对规模按常数递减的 T(n)=T(n−1)+f(n)、T(n)=2T(n−1)+f(n)，主定理不适用——只能逐层展开。这正是展开法必须掌握的原因。

:::

5. 最好、最坏与平均 ​

情况定义说明
最好计算量的最小值易求，但出现概率通常极小
最坏计算量的最大值上界保证，默认讨论的就是它
平均各输入等概率时计算量的加权平均值最贴近实际，但常难以确定

三档比的是同一 n 下的不同输入，别和大 O 混

O 描述的是函数关系（渐近上界），最好/最坏是在挑输入——两者正交。

「最坏情况是 O(n2)」和「平均情况是 O(n)」可以同时成立。直接插入排序遇升序最好 O(n)、遇逆序最坏 O(n2)，变的是初始状态。

默认约定

平均情况永远附带概率分布假设（不说明则默认等概率）。

由于平均情况往往难以确定，除非特别指明，讨论的时间复杂度一律指最坏情况——后面各章沿用，只在排序一章同时给三档。

6. 空间复杂度：数的是高度，不是结点数 ​

一个核心结论 ​

时间数递归树的结点总数，空间数递归树的高度

递归是深度优先展开的：左分支出栈后右分支才入栈，所以栈上任何时刻只躺着「根到叶」的一条路径。

每层只占常数空间时，S(n) 就等于递归工作栈的最大深度，而不是调用总次数。

什么计入、什么不计入 ​

项目是否计入
程序本身、常数否
输入数据本身否（占多大取决于问题，与算法无关）
额外申请的变量、数组是
递归工作栈是

典型情形 ​

算法递归深度其他辅助空间空间复杂度
阶乘 / 单链表递归遍历nO(1)O(n)
折半查找（递归）⌊log2⁡n⌋+1O(1)O(log⁡n)
汉诺塔nO(1)O(n)（时间虽是 O(2n)，栈上仍只有一条路径）
二叉树先序遍历树高 hO(1)最坏 O(n)、平衡时 O(log⁡n)
归并排序O(log⁡n)辅助数组 O(n)O(n)（两项取较大者）
快速排序平均 O(log⁡n)、最坏 O(n)O(1)平均 O(log⁡n)、最坏 O(n)
写大题时会用上：形参占不占空间

C 语言里数组作形参会退化成指针，void f(int a[], int n) 与 void f(int *a, int n) 完全等价，传的是首地址、不产生数组拷贝，只占 O(1)。

但结构体按值传入会真的拷贝：把含 MaxSize 数组成员的 SqList L 按值传给递归函数，每层都复制一整份，空间会从 O(深度) 变成 O(深度×结构体大小)。写成 SqList *L 或 SqList &L 就不会。

7. 真题怎么考 ​

考法 ​

几乎是同一道题的变体——给一段程序片段，问它的时间复杂度。

判断顺序固定：先看循环变量每次怎么变，再看有没有嵌套、内层依不依赖外层。

特征量级
每次乘 2（或除以 2）log 级。x = 2 * x 从 2 撑到 n/2，约 log2⁡n 次
每次加 1，但被平方约束n 级。i*i < n 等价于 i<n
每次加的量本身在变先求和再判。sum += ++i 直到 sum >= n，累加 1+2+⋯+i，解出 i≈2n
嵌套且内层与外层无关两层相乘。外层 k *= 2 走 log2⁡n 次、内层 n 次，合起来 O(nlog⁡n)
嵌套且内层上界就是外层变量不能相乘，要求和。外层 i *= 2、内层 j < i，总次数 1+2+4+⋯≈n，是 O(n)
递归只看规模怎么缩。fact(n-1) 是减 1，深度 n，O(n)

8. 易错清单 ​

易错一：嵌套循环里只看了一层

只盯外层 k *= 2 就答 O(log⁡n)、只盯内层 j<n 就答 O(n)，都是漏掉了另一层的乘法。

看到嵌套，先确认内层跑几次、外层跑几次，再决定是相乘还是求和。

易错二：「内层依赖外层」被当成了相乘

外层 log2⁡n 层、内层 j<i 时，每层的次数不一样，得按等比数列求和，答案是 O(n)；直接乘成 O(nlog⁡n) 就错了。

易错三：把「递归」和「对数」画等号

O(log⁡n) 对应的是规模每次减半（如折半查找）。

而 fact(n) = n * fact(n-1) 每次只减 1，深度是 n，时间是 O(n)。

易错四：开方当成了取对数

i*i < n 是 O(n)，不是 O(log⁡n)；只有乘除以常数才是对数级。

9. 速记 ​

三条会被反复调用的结论

  1. 分析的是基本操作的执行次数，不是运行时间——大 O 丢掉系数与低次项
  2. 递归的时间与空间量级可以差很远——时间数递归树的结点总数，空间数递归树的高度
  3. 主定理只管「规模按倍数缩小」的递归式，T(n)=T(n−1)+f(n) 一律逐层展开
