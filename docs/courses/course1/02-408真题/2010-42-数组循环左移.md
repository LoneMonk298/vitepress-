# 2010·42 数组循环左移：从辅助数组到三次逆置

> 本文改写自 [CodeBrick 408 数据结构讲义 · 2010·42 数组循环左移](https://www.codebrick.tech/ds-blog/posts/exams/2010-42-rotate-array)，原文链接保留。

这道题的题面把「时间和空间**两方面**都尽可能高效」写在了一起——两个约束同时收紧，暴力解不管走哪条路，总有一头卡住。

## 1. 题目与评分定位

### 符号约定

| 符号 | 含义 | 备注 |
|:---:|:---|:---|
| $n$ | 数组长度 | $n > 1$ |
| $p$ | 左移位数 | $0 < p < n$ |
| $R$ | 待处理的一维数组 | 记为 $(x_0, x_1, \ldots, x_{n-1})$ |
| $A$ | 前 $p$ 个元素构成的段 | $A = (x_0, \ldots, x_{p-1})$ |
| $B$ | 后 $n-p$ 个元素构成的段 | $B = (x_p, \ldots, x_{n-1})$ |
| $X^R$ | 序列 $X$ 的逆置 | 逆置是标准原地操作 |

---

### 题目原文

设将 $n$（$n>1$）个整数存放到一维数组 $R$ 中。试设计一个**在时间和空间两方面都尽可能高效**的算法，将 $R$ 中保存的序列循环左移 $p$（$0<p<n$）个位置，即将 $R$ 中的数据由 $(x_0,x_1,\ldots,x_{n-1})$ 变换为 $(x_p,x_{p+1},\ldots,x_{n-1},x_0,x_1,\ldots,x_{p-1})$。要求：

1. 给出算法的基本设计思想
2. 根据设计思想，采用 C 或 C++ 或 Java 语言描述，关键之处给出注释
3. 说明你所设计算法的时间复杂度和空间复杂度

总分 13 分（正确性 10 分、最优性 3 分）。

::: warning 本题的特殊之处
题面把「时间和空间两方面都尽可能高效」写在一起——**两个维度同时设卡**。

走「辅助数组」路线：时间达标，空间不达标
走「逐位挪」路线：空间达标，时间退化

两条暴力路线各卡一头，殊途同归。

:::

---

### 评分维度

| 维度 | 分值 | 要求 |
|:---|:---:|:---|
| **正确性** | 10 | 设计思想清楚、代码自洽、复杂度分析与实现一致 |
| **最优性** | 3 | 同时达到 $O(n)$ 时间 + $O(1)$ 空间 |

## 2. 暴力解：辅助数组暂存

### 设计思想

循环左移 $p$ 位，直观看就是「前 $p$ 个搬到末尾，后 $n-p$ 个整体前移」。麻烦在于原地搬会踩数据：$x_0$ 要去的位置上还住着别人。考场上最自然的补救：**先把前 $p$ 个抄出来存好，腾出地方让后面的整体前移，最后再把存的接回尾部**。

---

### 代码实现

```c
#include <stdlib.h>

void leftShift(int R[], int n, int p) {
    if (p <= 0 || p >= n) return;                // 边界保护：p 越界则不变
    int *tmp = (int *)malloc(p * sizeof(int));   // 暂存前 p 个，防止被踩
    if (tmp == NULL) return;                     // 分配失败保护

    for (int i = 0; i < p; i++)                  // ① 抄出前 p 个
        tmp[i] = R[i];
    for (int i = p; i < n; i++)                  // ② 后 n-p 个整体前移 p 位
        R[i - p] = R[i];
    for (int i = 0; i < p; i++)                  // ③ 暂存段接回尾部
        R[n - p + i] = tmp[i];

    free(tmp);
}
```

---

### 验证与复杂度

拿 $n=5$、$p=2$、$R=[1,2,3,4,5]$ 走一遍：抄出 $tmp=[1,2]$；前移后 $R$ 前三位变成 $[3,4,5]$；接回得 $[3,4,5,1,2]$。

::: info 第 ② 步的方向很关键
必须**从左往右**挪——目标位置 $i-p$ 永远在已读位置 $i$ 的左边，不会踩到还没读的数据。

:::

| 指标 | 值 | 说明 |
|:---|:---:|:---|
| 时间 | $\displaystyle \boxed{O(n)}$ | 三段循环合计 $p+(n-p)+p = n+p$ 次赋值 |
| 空间 | $\displaystyle \boxed{O(p)}$ | 辅助数组 `tmp` 占 $p$ 个 int，**不达标** |

时间已经线性了，卡在空间上。

---

### 另一条暴力路线：逐位挪

| 方案 | 时间 | 空间 | 卡在哪 |
|:---|:---:|:---:|:---|
| **辅助数组** | $O(n)$ | $O(p)$ | 卡空间 |
| **逐位挪** | $O(np)$ | $O(1)$ | 卡时间（重复搬运严重，每个元素被挪 $p$ 次） |

---

## 3. 暴力解的浪费在哪

### 三问审查

**一、有没有重复扫描？**

辅助数组版**没有**——每个元素只被搬动一次；倒是逐位挪版有严重的重复搬运（每轮只前进 1 位，同一个元素被挪 $p$ 次）。

**二、有没有重算已知的东西？**

没有。

**三、有没有放着性质不用？**

有，这是关键。

::: tip 循环左移是一个「置换」
辅助数组花 $O(p)$ 空间买的东西只有一样：**别把前 $p$ 个踩掉**。

但循环左移是一个**置换**——每个元素的去处从一开始就完全确定（下标 $i$ 的元素去 $(i-p+n) \bmod n$），没有任何信息需要「等一等再决定」。

置换原则上可以**原地完成**，缺的只是一个把它分解成原地步骤的招。

:::

---

### 那个招：逆置恒等式

把 $R$ 拆成两段 $A=(x_0,\ldots,x_{p-1})$、$B=(x_p,\ldots,x_{n-1})$，目标是 $AB \to BA$。

数学事实：

$$\boxed{(A^R B^R)^R = BA}$$

**两段拼接后整体逆置 = 各段先单独逆置再交换顺序**。而逆置本身是标准的原地操作——双指针从两端向中间交换，一个字节的额外数组都不用开。

---

## 4. 最优解：三次逆置

### 设计思想

顺着恒等式反着拆，就得到三步：

| 步骤 | 操作 | 结果 |
|:---|:---|:---|
| 起始 | — | $AB$ |
| 1：逆置 $R[0..p-1]$ | $A \to A^R$ | $A^R B$ |
| 2：逆置 $R[p..n-1]$ | $B \to B^R$ | $A^R B^R$ |
| 3：逆置整个 $R[0..n-1]$ | $(A^R B^R)^R$ | $BA$ |

拿 $n=5$、$p=2$、$R=[1,2,3,4,5]$ 验证：逆置前两个得 $[2,1,3,4,5]$；逆置后三个得 $[2,1,5,4,3]$；整体逆置得 $[3,4,5,1,2]$。

---

### 代码实现

```c
// 原地逆置 R[low..high]
static void reverse(int R[], int low, int high) {
    while (low < high) {
        int t = R[low];
        R[low] = R[high];
        R[high] = t;
        low++;
        high--;
    }
}

void leftShift(int R[], int n, int p) {
    if (p <= 0 || p >= n) return;       // 边界保护：p 越界则不变
    reverse(R, 0,     p - 1);           // 第 1 段逆置
    reverse(R, p,     n - 1);           // 第 2 段逆置
    reverse(R, 0,     n - 1);           // 整体逆置
}
```

---

### 复杂度

| 指标 | 值 | 说明 |
|:---|:---:|:---|
| 时间 | $\displaystyle \boxed{O(n)}$ | 三次逆置元素访问数 $= p+(n-p)+n = 2n$ |
| 空间 | $\displaystyle \boxed{O(1)}$ | 只用 `t`、`low`、`high` 三个标量 |

两个约束同时达标，这就是标准答案。

---

## 5. 四个易错细节

::: warning 易错点一：三次的顺序是硬性规定
必须先两段、后整体。

先整体再两段得到的是 $BA$ 的段内又各自逆置的错误形态，顺序错或漏一次都得不到目标序列，**按算法错处理**。

:::

::: warning 易错点二：段边界严格对齐
第 1 段是 $[0, p-1]$ 而非 $[0,p]$，第 2 段是 $[p, n-1]$ 而非 $[p+1, n-1]$。

off-by-one 直接改变分段位置，同样按算法错。

:::

**易错点三：reverse 的终止条件是 `low < high`**

两指针重合或交错即停。写成 `low <= high` 在偶数长度段会多做一次自交换，不影响正确性但属于白费操作。

**易错点四：(1) 问必须解释「为什么三次逆置等于循环左移」**

给出 $(A^R B^R)^R = BA$ 的推导，或举具体例子验证。只报操作步骤不给依据，设计思想那一问**要扣分**。

---

## 6. 等价方法与升级空间

### 等价方法对比

| 方法 | 时间 | 空间 | 判分定位 | 说明 |
|:---|:---:|:---:|:---|:---|
| 辅助数组 | $O(n)$ | $O(p)$ | 丢空间档 | 最直观，考场保底 |
| 逐位挪 | $O(np)$ | $O(1)$ | 丢时间档 | 每轮只前进 1 位 |
| 环式置换 | $O(n)$ | $O(1)$ | 与三次逆置等价 | 按 $\gcd(n,p)$ 个环分组搬运，代码更绕 |
| **三次逆置** | $\displaystyle \boxed{O(n)}$ | $\displaystyle \boxed{O(1)}$ | **满分** | 代码最简、最稳 |

---

### 升级空间

::: info 右移是免费赠品
循环右移 $p$ 位等价于左移 $n-p$ 位，三次逆置法直接套用。

同一思想还能解「字符串原地反转单词顺序」这类题——`reverse` 这个函数值得练成肌肉记忆。

:::

::: tip 考场策略
环式置换虽然也是最优解，但要处理环的分组与起点，代码明显更绕。

**考场上三次逆置是更稳的选择。**

:::

---

## 7. 总结

| 对比项 | 辅助数组 | 逐位挪 | 三次逆置 |
|:---|:---:|:---:|:---:|
| 时间 | $O(n)$ | $O(np)$ | $\displaystyle \boxed{O(n)}$ |
| 空间 | $O(p)$ | $O(1)$ | $\displaystyle \boxed{O(1)}$ |
| 得分 | 丢空间档 | 丢时间档 | **满分** |
| 核心 | 暂存防踩 | 用时间换空间 | 逆置分解置换 |

::: tip 备考要点
这道题的最优解只靠一个 `reverse` 函数，是历年真题里**性价比最高的升级之一**。

暴力解保底已经不差（13 分的大头在手），但三次逆置只需多写 8 行代码就能拿满。
