2013·41 主元素：从双重循环计数到摩尔投票 ​

本文改写自 CodeBrick 408 数据结构讲义 · 2013·41 主元素，原文链接保留。

2013 年这道 41 题，最优解是历年真题里最「反直觉」的一个——摩尔投票只用两个变量就找出了过半元素。但先别急着背它：这道题上暴力解的地位比你想的稳，13 分里它能拿下 11 分。

1. 题目与评分定位 ​

符号约定 ​

符号含义备注
A长度为 n 的整数序列记 A=(a0,a1,…,an−1)
ai序列第 i 个元素值域 0≤ai<n
n序列长度同时是元素值域的上界
x主元素候选出现次数必须严格超过 n/2
m候选 x 的出现次数判定条件 m>n2

题目原文 ​

已知一个整数序列 A=(a0,a1,…,an−1)，其中 0≤ai<n。若存在 ap1=ap2=⋯=apm=x 且 m>n/2，则称 x 为 A 的主元素。例如：

  • A=(0,5,5,3,5,7,5,5)，则 5 为主元素
  • A=(0,5,5,3,5,1,5,7)，则 A 中没有主元素

假设 A 中的 n 个元素保存在一个一维数组中，请设计一个尽可能高效的算法，找出 A 的主元素。若存在主元素，则输出该元素；否则输出 −1。要求：

  1. 给出算法的基本设计思想
  2. 根据设计思想，采用 C、C++ 或 Java 语言描述算法，关键之处给出注释
  3. 说明你所设计算法的时间复杂度和空间复杂度

评分维度 ​

这道题总分 13 分，按两个维度拆开：

维度分值拿分要点
正确性11思想清楚、代码自洽、边界正确、复杂度分析与实现一致
最优性2题面「尽可能高效」隐含要求 O(n) 时间 + O(1) 空间

关键信号

题面出现「尽可能高效」四个字，说明暴力解与最优解之间存在真实分差。若题面只说「设计算法」，则写对即可满分。

2. 暴力解：对每个元素数一遍 ​

设计思想 ​

主元素的定义就是「出现次数严格超过 n/2 的元素」。最直接的想法：

  • 对每个元素，从头到尾数一遍它出现了几次
  • 谁过半谁就是答案
  • 全部数完没人过半，输出 −1

代码实现 ​

c
int majority(int A[], int n) {
    for (int i = 0; i < n; i++) {
        int cnt = 0;
        for (int j = 0; j < n; j++)      // 从头数 A[i] 出现的次数
            if (A[j] == A[i]) cnt++;
        if (cnt * 2 > n) return A[i];    // 严格过半即为主元素
    }
    return -1;                           // 无任何元素过半
}

边界细节：过半判定必须严格 ​

唯一必须写对的细节

过半判定是严格大于，写作 cnt×2>n，不要写成 ≥。

  • n=8 时某元素出现 4 次：4×2=8 不大于 8，不算主元素
  • 用整数乘法而非 cnt>n/2 可避免截断歧义

复杂度 ​

指标值说明
时间O(n2)双重循环，外层每个 i 都触发一轮完整内层统计
空间O(1)只用 cnt 一个计数器

3. 暴力解的浪费在哪 ​

三问审查 ​

一、有没有重复扫描？

有，而且形态很典型。外层每换一个 i 就把整个数组从头扫一遍。更扎眼的是：若 5 在数组中出现了 5 次，「数 5 出现几次」这件事就被完完整整做了 5 遍——同一个值的每次出现都触发一轮相同的全表统计。

二、有没有重算已知的东西？

有。内层比较产生的「相等/不等」信息用完即弃，下一轮从零开始。

三、有没有放着性质不用？

有，而且是决定性的。

「过半」是个极强的结构性质

如果主元素存在，它比其余所有元素加起来还要多。

把任意一个主元素和任意一个非主元素配对抵消，抵消到最后主元素必然有剩余。这意味着根本不需要给每个值分别计数——只要维护「当前领先者和它的净票数」就够了。

中间站：计数数组 ​

顺着前两个浪费走，能到一个中间站：题面给了 0≤ai<n 的值域，开一个长度 n 的计数数组，值直接当下标，一遍扫描全部计完。它消灭了重复扫描，却没碰「过半」这个性质。

方案时间空间消灭了什么没碰什么
双重循环O(n2)O(1)—重复扫描 + 过半性质
计数数组O(n)O(n)重复扫描过半性质
摩尔投票O(n)O(1)重复扫描过半性质也用上

把第三问也用上，就是摩尔投票。

4. 最优解：摩尔投票 ​

设计思想 ​

第一遍：投票互抵选候选。 维护候选 candidate 和净票数 count，从左到右扫：

情形动作
count == 0当前元素上位成为新候选，count = 1
当前元素 == candidatecount++（同伴加票）
当前元素 != candidatecount--（敌对抵消一票）

若真主元素 x 存在，每一对（x、非 x）抵消后至少还剩 1 张 x 的票，扫完 candidate 必是 x。

第二遍：验证。 第一遍只保证「如果主元素存在，candidate 就是它」，不保证「candidate 一定是主元素」——没有主元素时 candidate 可能是某个撑到最后的普通元素。所以要再扫一遍数出 candidate 的真实出现次数，严格过半才输出。

代码实现 ​

c
int majority(int A[], int n) {
    int candidate = A[0];
    int count = 1;

    // ① 第一遍：投票互抵选出候选
    for (int i = 1; i < n; i++) {
        if (count == 0) {                  // 上一组票抵光，重启候选
            candidate = A[i];
            count = 1;
        } else if (A[i] == candidate) {
            count++;                       // 同伴：票数加
        } else {
            count--;                       // 敌对：相互抵消
        }
    }

    // ② 第二遍：验证候选的真实出现次数是否过半
    int times = 0;
    for (int i = 0; i < n; i++) {
        if (A[i] == candidate) times++;
    }

    return (times * 2 > n) ? candidate : -1;
}

正确性论证 ​

为什么两遍扫描是对的

第一遍的必要性

设主元素 x 出现 m>n/2 次，其余元素共 n−m<n/2 个。每次抵消消耗一个 x 和一个非 x，最多抵消 min(m, n−m)=n−m 次。抵消完后 x 至少剩：

2m−n>0

因此 candidate 最终必为 x。

第二遍的必要性

没有主元素时，candidate 只是「撑到最后的普通元素」，不代表它过半，必须重新计数验证。

复杂度 ​

指标值说明
时间O(n)两遍线性扫描，合计 2n 步
空间O(1)只用 candidate、count、times 三个标量

这就是标准答案，两个维度全部拿满。

5. 四个易错细节 ​

从暴力解升级过来，这四个细节决定 13 分能拿多满：

易错点一：第二遍验证绝不能省

这是本题最高频的错点。

拿题面第二个例子 A=(0,5,5,3,5,1,5,7) 走一遍第一轮：5 会几度上位又几度被抵光，扫完 candidate = 5、净票数为 0；但 5 实际只出现 4 次，不过半。

不验证就会把「没有主元素」误判成「主元素是 5」。暴力解里「数出来的就是真实次数」是免费的，投票互抵后这个保证消失了，必须自己补回来——这是暴力升级最优时典型的「免费性质要重新自己买单」。

易错点二：count == 0 时必须同时重置 candidate

只把 count 置 1 而不换候选，等于让已经被抵光的旧候选白拿一票，按错处理。

易错点三：加减方向别写反

同伴 count++、敌对 count--；写反后整个投票语义颠倒。

易错点四：输出约定照题面

找不到返回 −1，既不是 0 也不是别的哨兵值；过半判定沿用严格大于。

6. 等价方法与升级空间 ​

等价方法对比 ​

方法时间空间判分定位说明
计数数组O(n)O(n)只拿正确性分值域 0≤ai<n 保证值可当下标
排序后取中间O(nlog⁡n)O(1)只拿正确性分主元素若存在必覆盖中间位置，取出后仍要数一遍验证
哈希表O(n)O(n)只拿正确性分值域不受限时的通用计数方案
摩尔投票O(n)O(1)满分唯一同时满足两个维度的解

升级空间 ​

找出现次数超过 n/k 的元素

摩尔投票有推广形式：找「出现次数 >n/k」的所有元素，同时维护 k−1 个候选做抵消。

考研只考 k=2 的基础形式，但理解「抵消后必有剩余」这个核心论证后，推广是顺理成章的。

7. 总结 ​

对比项暴力解（双重循环）最优解（摩尔投票）
时间O(n2)O(n)
空间O(1)O(1)
得分11 / 13（正确性满分）13 / 13（满分）
核心思想每个元素数一遍投票互抵 + 验证
关键坑过半判定用严格大于第二遍验证不能省

备考路线

先写对暴力解把 11 分拿到手，再理解「过半」的结构性质升级到摩尔投票拿满 13 分。

不要一上来就背摩尔投票——背下来的模板在考场上遇到变体会立刻失效，理解「抵消后必有剩余」的论证才能真正迁移。
