# 2009·42 倒数第 k 个结点：从两遍扫描到双指针

> 本文改写自 [CodeBrick 408 数据结构讲义 · 2009·42 倒数第 k 个结点](https://www.codebrick.tech/ds-blog/posts/exams/2009-42-find-kth-from-tail)，原文链接保留。

这是全专题里暴力解和最优解离得最近的一道题：暴力解已经是 $O(n)$ 时间、$O(1)$ 空间，最优性档卡的只剩「扫两遍还是扫一遍」。也正因为差距小，这次升级几乎是白捡的——而它练出来的双指针，是后面一串链表题的地基。

## 1. 题目与评分定位

### 符号约定

| 符号 | 含义 | 备注 |
|:---:|:---|:---|
| $n$ | 链表中数据结点的个数 | 不含头结点 |
| $k$ | 倒数位置，正整数 | 题面要求 $k$ 为正整数 |
| $list$ | 头指针 | 指向**头结点**，头结点不存数据 |
| $fast$ | 前指针 | 先走 $k$ 步探路 |
| $slow$ | 后指针 | 与 $fast$ 保持 $k$ 个结点间距 |

---

### 题目原文

已知一个带有表头结点的单链表，结点结构为：

```text
┌──────┬──────┐
│ data │ link │
└──────┴──────┘
```

假设该链表只给出了头指针 $list$。在不改变链表的前提下，请设计一个**尽可能高效**的算法，查找链表中倒数第 $k$ 个位置上的结点（$k$ 为正整数）。若查找成功，算法输出该结点的 `data` 域的值，并返回 1；否则，只返回 0。要求：

1. 描述算法的基本设计思想
2. 描述算法的详细实现步骤
3. 根据设计思想和实现步骤，采用程序设计语言描述算法（使用 C、C++ 或 Java），关键之处给出简要注释

总分 15 分。

::: warning 两条硬性要求
1. 题面写了「尽可能高效」——最优性分存在
2. **不改变链表**——任何版本都只能读、不能写

:::

---

### 评分维度

| 维度 | 说明 |
|:---|:---|
| **正确性** | 正确定位倒数第 $k$ 个、$k$ 越界返回 0、成功时输出 `data` 返回 1、不改动链表 |
| **最优性** | 本题看的是**扫描遍数**——双指针一遍扫描是标答，两遍扫描丢一小档 |

::: tip 题库原话
先求长度再走 $n-k$ 步的两遍扫描「**也对**」——它拿到正确性主体分，只丢最优性里很小的一档。

:::

---

## 2. 暴力解：两遍扫描

### 设计思想

「倒数第 $k$ 个」换算成正数很简单：链长为 $n$ 时，倒数第 $k$ 个就是**正数第 $n-k+1$ 个**。麻烦在于单链表不自带长度——那就先扫一遍数出来：

- 第一遍：从首结点走到尾，数出长度 $n$
- 判断：若 $k > n$，链不够长，返回 0
- 第二遍：从首结点再出发，走 $n-k$ 步，停下的位置就是倒数第 $k$ 个

---

### 代码实现

```c
typedef struct LNode {
    int           data;
    struct LNode *link;
} LNode, *LinkList;

int findKthFromTail(LinkList list, int k) {
    // ① 第一遍：数出链表长度 n（从 list->link 起，不含头结点）
    int n = 0;
    for (LNode *p = list->link; p != NULL; p = p->link) n++;

    if (k > n) return 0;               // 链长不足，查找失败

    // ② 第二遍：从首结点走 n - k 步，到达正数第 n-k+1 个
    LNode *p = list->link;
    for (int i = 0; i < n - k; i++) p = p->link;

    printf("%d", p->data);             // 输出倒数第 k 个结点的 data
    return 1;
}
```

---

### 验证与复杂度

拿链 $1 \to 2 \to 3 \to 4 \to 5 \to 6$、$k=2$ 走一遍：第一遍数出 $n=6$；$6 \ge 2$ 不越界；第二遍走 4 步落在值为 5 的结点上，输出 5 返回 1。

| 指标 | 值 | 说明 |
|:---|:---:|:---|
| 时间 | $\displaystyle \boxed{O(n)}$ | 两遍各走一次链，约 $2n$ 次指针移动 |
| 空间 | $\displaystyle \boxed{O(1)}$ | 只用 `p`、`n`、`i` 几个标量 |
| 约束 | 满足 | 全程只读不写，「不改变链表」达标 |

---

## 3. 暴力解的浪费在哪

### 三问审查

**一、有没有重复扫描？**

有。整条链被走了两遍，而第一遍走完只带走**一个数字 $n$**，沿途看到的所有结点位置信息全部扔掉了，第二遍只能从头再来。

**二、有没有放着性质不用？**

有，而且就是解题钥匙。

::: tip 「倒数第 k 个」的本质
「倒数第 $k$ 个」= 「**距离链尾恰好 $k$ 个结点**」。

要判断这件事，其实不需要知道总长 $n$——只要有另一个游标在前面 $k$ 步替你探路：**探路的到了链尾，你就正好在倒数第 $k$ 个**。

「先数 $n$ 再算 $n-k$」是绕了远路，把一个相对位置问题做成了绝对位置问题。

:::

---

### 对策

用总纲的第一类手段——**一遍扫描时多记一点**：多带一个指针，把「距离」直接编码在两个指针的间隔里。

---

## 4. 最优解：双指针一遍扫描

### 设计思想

让 $fast$、$slow$ 都从首结点出发：$fast$ 先走 $k$ 步，然后两人同步前进、始终保持 $k$ 个结点的间距。当 $fast$ 越过链尾（NULL）时，$slow$ 距链尾正好还差 $k$——它就是倒数第 $k$ 个。若 $fast$ 在先走的 $k$ 步里就撞上 NULL，说明链长 $< k$，返回 0。

::: info 数学验证
链长 $n$，$fast$ 先走 $k$ 步后，两人再同步走 $n-k$ 步 $fast$ 到达 NULL，此时 $slow$ 从首结点走了 $n-k$ 步，指向正数第 $n-k+1$ 个，正是倒数第 $k$ 个。

:::

---

### 代码实现

```c
typedef struct LNode {
    int           data;
    struct LNode *link;
} LNode, *LinkList;

int findKthFromTail(LinkList list, int k) {
    LNode *fast = list->link;          // 跳过头结点，从首结点开始
    LNode *slow = list->link;
    int i = 0;

    // ① fast 先走 k 步；若途中遇 NULL，说明链表长度 < k
    while (fast != NULL && i < k) {
        fast = fast->link;
        i++;
    }
    if (i < k) return 0;               // 长度不足，查找失败

    // ② 两指针同步前进，fast 到 NULL 时 slow 即倒数第 k 个
    while (fast != NULL) {
        fast = fast->link;
        slow = slow->link;
    }

    printf("%d", slow->data);          // 输出倒数第 k 个结点的 data
    return 1;
}
```

---

### 复杂度

| 指标 | 值 | 说明 |
|:---|:---:|:---|
| 时间 | $\displaystyle \boxed{O(n)}$ | $fast$ 总共走完整条链一次（前 $k$ 步 + 后 $n-k$ 步 $=n$ 步） |
| 空间 | $\displaystyle \boxed{O(1)}$ | 只有 `fast`、`slow`、`i` 三个标量 |

这就是标准答案。

---

## 5. 四个易错细节

::: warning 易错点一：fast 先走 k 步，不是 k-1 步
间距必须恰好是 $k$：$fast$ 到 NULL 那一刻 $slow$ 才落在倒数第 $k$ 个上。

先走 $k-1$ 步会让 $slow$ 停在倒数第 $k+1$ 个，**差一个结点**。

:::

::: warning 易错点二：越界判定藏在先走的循环里
循环条件写 `fast != NULL && i < k`，走完检查 `i < k` 就返回 0。

漏掉这个判定，链长不足时会带着错误状态进入同步循环，逻辑全乱——这是本题**最常见的丢分点**。

:::

**易错点三：从 `list->link` 起步，不是 `list`**

题面是带头结点的链表，头结点不存数据；从 $list$ 起算会整体错位一个结点。

**易错点四：只读不写**

「不改变链表」是题面的硬性要求，$fast$、$slow$ 只是游标，不能改 `link` 域、不能 `malloc`/`free`。两遍扫描版天然满足，双指针版也一样——升级不引入任何写操作。

---

## 6. 等价方法与升级空间

### 等价方法对比

| 方法 | 时间 | 空间 | 判分定位 | 说明 |
|:---|:---:|:---:|:---|:---|
| 两遍扫描 | $O(n)$ | $O(1)$ | 丢一小档最优性 | 先数 $n$，再走 $n-k$ 步 |
| 栈法 | $O(n)$ | $O(n)$ | 丢更多最优性 | 全部压栈再弹 $k$ 次，辅助栈占 $O(n)$ |
| **双指针** | $\displaystyle \boxed{O(n)}$ | $\displaystyle \boxed{O(1)}$ | **满分** | 单趟扫描，间距编码位置 |

---

### 升级空间：双指针家族

::: info 同一个技巧的三个变体
本题的「$fast$ 提前 $k$ 步」和下面两个是同一技巧的不同形态：

- **找中点**：$fast$ 走 2 步、$slow$ 走 1 步
- **判环**：$fast$ 走 2 步、$slow$ 走 1 步，相遇即有环

找中点那个变体正是 2019·41 链表重排三步原地解的第一步——这道 2009 年的题，练的是后面十几年反复出现的基本功。

:::

---

## 7. 总结

| 对比项 | 两遍扫描 | 双指针一遍 |
|:---|:---:|:---:|
| 时间 | $O(n)$（约 $2n$ 步） | $\displaystyle \boxed{O(n)}$（$n$ 步） |
| 空间 | $O(1)$ | $O(1)$ |
| 扫描遍数 | 两遍 | **一遍** |
| 得分 | 正确性满分，丢最优性小档 | 满分 |
| 核心 | 先数长度再定位 | 间距编码相对位置 |

::: tip 备考要点
这是全专题里暴力解**最保值**的一道：渐进复杂度已经和最优解持平，丢的只是很小一档。

复杂度那问照实写「两遍扫描、时间 $O(n)$、空间 $O(1)$」——分析与实现一致本身就是得分点。

:::
